# 黑马点评项目技术说明

## 项目定位

这是一个基于 Spring Boot、MyBatis-Plus、MySQL、Redis、Nginx 的本地生活后端项目，核心目标是解决高并发场景下的缓存查询、登录态管理和秒杀下单问题。

## 当前可写入简历的亮点

### 1. 商户缓存设计

- 基于 Redis 实现商户详情缓存，封装了缓存穿透保护与逻辑过期能力。
- 使用互斥锁控制热点 Key 的缓存重建，避免大量请求同时回源数据库。
- 通过 Lua 脚本实现“比较锁值 + 删除锁”的原子解锁，避免锁误删问题。

### 2. 秒杀异步下单链路

- 在 Redis 侧通过 Lua 脚本完成库存校验和一人一单预校验，降低数据库压力。
- 使用异步线程池执行下单操作，实现请求削峰。
- 结合 Redisson 分布式锁与事务方法，保证同一用户不会重复创建订单。

### 3. 登录态与用户能力

- 基于 Redis Hash + token 实现无状态登录。
- 通过拦截器刷新 token TTL，减少 Session 依赖。
- 支持用户签到与连续签到统计，使用 Redis Bitmap 压缩签到状态。

### 4. 社交流能力

- 基于 Redis ZSet 实现关注推送和滚动分页查询。
- 支持博客点赞、点赞排行榜和关注 Feed 流查询。

### 5. 全局唯一 ID

- 基于时间戳 + Redis 自增计数生成全局唯一订单 ID。
- 兼顾趋势递增和高并发下的唯一性需求。

## 面试建议讲法

### 商户缓存

可以重点讲三种缓存问题：

1. 缓存穿透：空值缓存兜底。
2. 缓存击穿：热点数据使用逻辑过期 + 互斥锁异步重建。
3. 锁误删：使用 Lua 将比较 owner 和删除操作做成原子操作。

### 秒杀设计

建议按“请求进入 -> Redis 预校验 -> 异步削峰 -> 加锁防重 -> 事务落库”这条链路讲。

## 当前版本边界

- 附近商铺和 GEO 查询常量已预留，但后端检索链路还未真正完成。
- 秒杀异步链路当前仍是 JVM 内阻塞队列，适合单机演示，不适合直接描述为分布式消息队列架构。
- 项目仍以演示型单体架构为主，工程化和监控能力有继续提升空间。

## 后续升级方向

### RabbitMQ 版秒杀异步链路

可将当前 JVM 内阻塞队列升级为 RabbitMQ：

- 生产者负责资格校验后发送下单消息。
- 消费者负责创建订单、扣减库存和幂等控制。
- 可以继续补充失败重试、重复消费处理、死信队列和消息堆积治理。

这一升级完成后，可将项目进一步包装为“高并发秒杀系统的异步削峰架构演进”案例。
